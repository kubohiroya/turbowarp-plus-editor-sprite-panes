# TurboWarp Plus Editor Sprite Panes

TurboWarp Plus Editor のスプライトと背景の編集タブの中に置くペイン。各ペインは React の部品で、選択中の対象のデータを受け取り、編集をコールバックで返す。ペインをタブや分割に並べるのは `@kubohiroya/turbowarp-plus-editor-layout` の役目。

## ペイン

| export | 役割 |
| --- | --- |
| `./sprite-asset-pane` | `SpriteAssetPane` はコスチュームや音を一覧し、ペインが非アクティブでも選択を保つ。「変数」では変数を一覧し、値の編集を一度だけ確定し、Scratch と同じ形のダイアログで変数を作成・改名・削除する。`NativeAssetPanel` は GUI 自身の素材一覧を収める |
| `./sprite-message-pane` | `SpriteMessagePane` は「送信」「受信」の2枚のタブで、その対象が送る側・受け取る側となるメッセージの関係図を描く。送信元には送っているスクリプトのハットを添え、押すとそのブロックを開く。受け取るブロックや送るブロックのない側には警告の印を付ける。メッセージ名は、関係図の名前の右の ▼ から開くメニューでダイアログを開いて変える |
| `./sprite-function-pane` | `SpriteFunctionPane` は、スプライトやステージの関数（ブロック定義と、named-functions 拡張の名前付き関数）を一覧する。名前付き関数は `kubohiroyanamedfunctions` の拡張から読み、Composition API で同じブロックを持つ拡張の ID も `readTargetFunctions` に渡せる。並べ方は名前順・Z順（行ごと）・N順（列ごと）から選ぶ。呼び出し関係を左から右（LR）か上から下（TD）に流れる図でも表示できる（流れはホストがタブ選択レールの下端に置く `FunctionFlowToggle` で切り替え、`direction` で図へ渡す。図は呼び出し関係で関数を置くので、並べ方は一覧だけで選ぶ）。図はコード領域と同じく、ドラッグとホイールで動かし、− + = のボタンと Ctrl + ホイールで拡大縮小し、ミニマップを出す。関数にポインターを重ねるかフォーカスすると、その関数に入るリンクと出るリンク、その先の関数を強調する。`view` を渡すと一覧か図の一方だけを表示し（それぞれを独立したセクションにするとき）、一覧ではホストが `hats` で渡すハットのスクリプトも関数の上に並べ（`thumbnail` を渡せばハットの絵を添える）、`onOpenScript` で開く。名前付き関数は、標準の関数の下の「TurboWarp Plus 名前付き関数」にまとめる。関数には f(x) の印を付け、ホストが `selectedId` で示す項目を強調表示する。関数の「x か所で使用」を押すと、その関数を呼ぶブロックの一覧（`readTargetFunctions` が読む `uses`）をダイアログで示し、選ぶと `{block}` を添えてそのスクリプトを開く。一覧や図で選んだ関数は、ホストの `onOpenFunction` で開く（ペインの横のタブなど）。`onOpenFunction` が無ければダイアログで開く。`readTargetFunctions` に `others` でほかのスプライトとステージを渡すと、その中のグローバル関数（すべてのスプライト向けの名前付き関数）のうち、この対象の関数が呼ぶものと、この対象のグローバル関数を呼ぶものを `globals` に読む。図はグローバル関数を灰色の背景・白抜きの文字で描き、ほかの対象のものには定義した対象の名前を添える（ホストが所有者情報を使って開く）。一覧には出さない。図では、呼び出しも呼ばれもしない関数を、ほかの関数から間を空けて下の段に並べる。ホストが `onCreate` を渡すと、一覧の下と図の左下に「＋ 新しい関数を追加」のボタンが出る。関数が無いときも図は白紙で描き、中央の警告で左下のボタンへ案内する（一覧では下のボタンへ）。押すとダイアログで関数名と種類（標準のブロック定義か TurboWarp-Plus の名前付き関数。前回の種類を覚える）を尋ね、`onCreate(kind, name)` で作った関数を開いて選択する。ダイアログでは、その定義スクリプトの編集画面をホストが差し込む要素を渡す。`readTargetFunctions` が VM の対象から定義を読む |
| `./sprite-properties` | `SpritePropertiesPanel` は設定フォーム。ペインの幅に合わせて折り返し、選択が変わった場合の古い編集を拒み、VM に更新を反映する。`createSpriteInfoAdapter` は GUI のスプライト情報に接続する |
| `./sprite-editor-toolbar` | `SpriteEditorToolbar` は「自由配置」（コード領域）「ハット・関数一覧」「呼び出し関係」｜「コスチューム / 背景」「音」｜「変数」「メッセージ」を切り替える縦のレール（3つの群の間に線を引く）と、表示中のセクションの検索欄 |
| `./temporary-variables` | `readTemporaryVariables` は一時変数拡張（`lmsTempVars2`）のうち、コード中で名前を固定テキストで書いたスレッド変数（背景ではランタイム変数も）を、値を入れる関数（ブロック定義）と読み取り・変更の数とともに集める。ランタイム変数では、定義（〜にする）・参照（読む、有無を調べる）・書き換え（〜ずつ変える、削除する）のそれぞれを行う関数を、そのスプライトの名前とともに集める。デバッガーで一時停止している間は、その時点の値と、実行時に名前を組み立てた変数も加える。`watchTemporaryVariables` は一時停止・再開と、一時停止中の値の変化を知らせる。`SpriteAssetPane` は受け取った一覧を、スプライト変数・グローバル変数の後に「スレッド変数」「ランタイム変数」として並べる。ランタイム変数の「参照している関数」「書き換えている関数」には、その関数の数をバッジで添える。`getInspectorVariables()` を持つ拡張（`runtime.ext_<id>`、`InspectorVariableProvider`）は、Scratch の変数ではない独自の変数（TurboWarp紙芝居の物語変数など）を背景の変数ペインに出せる。表は拡張が名付けた見出しで並べ、値はデバッガーで一時停止している間だけ表示する |
| `./sprite-clone-inspector` | `SpriteClonePagination` は、実行中のクローンを選んで「プロパティと変数」に表示する。クローンが5体までは番号のボタン、それより多いときは前後の矢印と番号の選択欄で選ぶ。クローンがスプライト変数 `actorName` に名前を持つとき（TurboWarp紙芝居は1つのスプライトのクローンで複数のアクターを演じ、この変数で区別する）は、番号の代わりにアクター名の選択欄で選ぶ。同じ名前のクローンにはクローン番号を添える。`SpriteCloneVariables` は選んだクローンの値を表示・編集する |
| `./block-image` | `createBlockImageRenderer` は、どの対象のブロックでも、Scratch と同じ見た目で 1 つだけ描く。編集中の対象しか描かない Editor の代わりに、画面外のワークスペースで描いてその複製を返す。ScratchBlocks は Editor が渡し、このパッケージは import しない。`BlockImage` はその絵をペインに置く部品で、描けないときは名前の文字で代える。`hatName` はハットの名前を返す。変数ペインの一時変数の表と、メッセージペインの「から始まるスクリプト」・受信のハットがこれを使う |
| `./script-start` | `scriptStartOf` と `describeScriptStart` は、ブロックがあるスクリプトの始まりを、ハット・関数（ブロック定義）・TurboWarp Plus の名前付き関数のどれかとして返す。メッセージペインの関係図の送信元と、一時変数の表が使う |
| `./native-tile-title` | `observeTileNameTitles` は GUI のスプライト一覧の各タイルに、名前全体をツールチップとして付ける。一覧が後からタイルを差し替えても付け直す |

スタイルシートのあるペインは `<ペイン>.css` として export する。グローバルなスタイルシートとして読み込む。表示は英語で、`locale` が `ja` で始まるときは日本語。

呼び出し関係の図とミニマップで、関数を呼ぶ矢印は Editor 共通の `--tw-script-function-stroke` を使う紫系の実線に統一する。トークンを渡さないホストでも明暗に応じた同じ配色を使う。再帰や循環も実線とし、選択した関数に入る・出る矢印は太さと不透明度で強調する。ノードを囲む呼び出し元・呼び出し先のリングは従来の色を保つ。コード領域のメッセージ送信を表す橙系の破線とは区別する。

`SpriteEditorToolbar` の `sectionControls` は、タブ一覧とは別の領域として選択レールの下端に表示する。ホストは「呼び出し関係」セクションで `FunctionFlowToggle({locale, value, onChange})` と `FunctionRelationToggles({locale, value, onChange})` を渡す。方向は左右・上下のアイコンを持つ `LR` と `TD` の2ボタンから1つだけを選択するグループで、選択済みを押しても解除しない。各ボタンはEnter・Spaceでも選択でき、ツールチップで方向を説明する。「関数」と「メッセージ」のボタンは各種類の関係を個別に表示・非表示にし、ツールチップに対象と操作を説明する。図内には方向切り替えや常設の凡例を置かない。`SpriteFunctionPane.direction` と `relationVisibility` は保存済みの設定より優先し、一覧の並べ方や追加する関数の種類を変えたときの `onSettingsChange` にも、その時点の方向と表示設定を保持する。

下端では方向と種類別表示をそれぞれ縦に連結したグループにし、グループ間をボタンの高さの半分（20px）空ける。文字・アイコンは正立させ、各ボタンは32×40pxとする。種類別表示は上を関数、下をメッセージとする。表示中の種類にはホストのアクセント色 `--looks-secondary` と白いアイコンを使い、特定のアクセント色には固定しない。最下段は「新しい関数を追加」ボタンの下端に揃える。上部の表示内容選択ボタンは従来の寸法を保つ。

呼び出し関係の図へは、`FunctionPaneData.scriptRelations` に関数・メッセージの接続、`scripts` にハットやスクリプトの表示名・対象・位置を渡す。メッセージの線は橙系の破線、関数の線は紫系の実線で、ミニマップも同じ区別を使う。同じノード間に関数とメッセージの両方があるときは、種類ごとに分けた2本の矢印を描く。メッセージは送信方式ごとにまとめ、受信側のラベルに「💬 メッセージ名」を列挙する。「送って待つ」は従来の線7・間隔5の破線、「送る」は線3.5・間隔2.5の細かい破線で区別し、砂時計アイコンは表示しない。両方の送信方式があるときは別の経路に描き、ミニマップにも同じ線種を使う。外部関数では矢印に関数名、先のノードにスプライト名・背景を示し、重複させない。外部メッセージの対象名はノード、メッセージ名は矢印に分けて示す。矢印の角丸ラベルに対象名を重複表示しない。ラベルも配置とミニマップの表示範囲に含める。関数を表示するときは、呼び出されていない定義も残す。ハットなどのスクリプトは表示中の関係に必要なものだけを表示し、選ぶと `onOpenRelationScript({targetId, scriptId, blockId})` で開く。これらを関数の編集画面へ渡さない。通常の関数ノードは従来の `onOpenFunction` を使う。

呼び出し関係の図ではノードをドラッグして配置を変えられる。背景のドラッグは図全体の移動、ノードの通常クリックやキーボード操作は従来どおりスクリプトを開く。矢印・受信側ラベル・ミニマップは手動配置に追従する。図内の位置だけを `FunctionPaneSettings.graphPositions[targetId][LR|TD][nodeId]` に保存し、作品のブロック位置は変えない。方向ごとに配置を保ち、表示種別を切り替えて戻したときも復元する。ドラッグ完了時に `onSettingsChange` でホストへ渡すので、既存のペイン設定の保存経路で再表示できる。取り消しやペインの破棄時は未確定の移動を保存しない。

`selectedId` と `focusRequest` を渡すと、指定スクリプトを図の中央へ置き、その呼び出し元・先を強調する。同じスクリプトへの再要求では `focusRequest` の数値を変える。呼び出し関係のないハットも、この要求の対象ならノードを表示する。表示中のパン・ズームや手動配置は引き続き操作でき、要求は作品データへ保存しない。切り戻す場合は `focusRequest` を渡さない。

メッセージの読み取りと変数の編集は `@kubohiroya/turbowarp-plus-editor-project-model` を使うので、これらのペインと Editor の作品内検索は作品を同じように判定する。

Editor は GUI の React 16 にこれらを描画するので、React 16.14 以降に対応する。

## 検証

`npm test` でビルドし、React 16.14 より新しい API を使っていないことと、メッセージペインとスプライト情報の接続を確かめる。`npm run test:browser` で素材ペイン、設定フォーム、ツールバーを Chromium で操作する。

npm への公開は `.github/workflows/release.yml` が行う。`package.json` の版が npm にまだ無いときだけ、テストを通したうえで公開する。認証は npm の Trusted Publisher（OIDC）で、npm 側の設定にはこのワークフローのファイル名をそのまま登録する。

## ライセンス

MPL-2.0。`@kubohiroya/turbowarp-plus-editor-layout` から切り出したペインで、その履歴をこのリポジトリに残している。設定フォームは以前のスプライト設定ソース `80825f7` から移設した。GPL のコードを含まず、GPL のモジュールも import しない。

`readTargetFunctions(target, {others, describeScript})` は従来どおり共通のメッセージ走査から `messageGraph` を返す。`describeScript(targetId, scriptId)` は任意のハット表示名を渡す。`scriptRelations` を指定しないホストでもこのデータを図に使え、通常のスクリプトを `onOpenScript` に元の `id` と `targetId` で渡す。外部の関数は `onOpenFunction` に `owner` を渡す。既存の `showCalls` / `showMessages` 設定も矢印だけの表示設定として扱い、ノード位置・ズームを保つ。新しいレールの操作は `relationVisibility` に接続する。どちらも値を省略すると表示する。作品データの移行はなく、切り戻しはホストのパッケージ固定を変更前へ戻して再ビルドする。

外部関数ノードには、`readTargetFunctions` の `getTargetThumbnail(targetId)` で渡した現在のコスチューム・背景を名前の前に添える。画像は `GlobalFunctionOwner.thumbnailUrl` に保持し、画像を渡さないホストでは名前だけを表示する。

関係図の通常ノードは、上段にハット・関数の名前、下段に対象の名前を分けて表示する。長い名前は省略せず折り返し、図内共通のノード高さを必要な行数へ広げる。矢印の端点・受信側ラベル・ミニマップ・手動配置の表示範囲も同じ高さへ追従する。灰色の外部関数ノードはサムネイルと対象名だけを表示し、長い対象名も折り返す。
